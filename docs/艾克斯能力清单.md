## 二、消息处理主链路

艾克斯当前的飞书消息处理链路如下：

1. 飞书 `im.message.receive_v1` 进入 `src/feishu/client.ts`
2. `src/index.ts` 完成去重、消息长度校验、图片识别分流
3. `src/core/message-router.ts` 进行话题路由和上下文装配
4. `src/core/agent-loop.ts` 运行主 Agent Loop，按需调用工具
5. 回复通过飞书 SDK 回发到原始会话
6. `background-memory.ts` 异步提取记忆、话题关系和执行摘要

当前处理特性：

- 文本消息
- 图片消息（视觉识别 + 用户问题注入）
- 长消息拒绝保护
- 命令前缀识别
- Clarify 追问卡片 / 等待用户回复
- 话题级 history bucket
- 多话题拆分并行处理

## 七、飞书与外部接口

### 7.1 飞书原生集成

当前飞书主链路由 `@larksuiteoapi/node-sdk` 驱动：

- WebSocket 收消息
- 文本 / 图片消息处理
- 富文本回复
- 卡片按钮动作
- 文件 / 图片下载
- 长消息拆分发送

### 7.2 HTTP Hooks API

默认端口：`8081`

当前接口包括：

- `/health`
- `/health/detailed`
- `/api/models`
- `/api/models/:id`
- `/api/sessions/stats`
- `/api/sessions/clear`
- `/api/chat`
- `/api/hooks`
- `/api/hooks/trigger`
- `/api/hooks/:type/register`
- `/test/message`
- `/api-docs.json`

其中：

- `/test/message` 当前已改为**必须配置并提供 `XDEV_API_TOKEN`** 才能调用
- 该接口会把测试消息注入完整处理管道，并让回复按正常飞书路径发送

### 7.3 Gateway 控制平面

默认端口：`18789`

能力包括：

- WebSocket 健康检查
- 会话列表
- 配置读取
- 插件状态
- 通道状态

## 十、当前版本最重要的新增能力

本轮迭代相较旧版，最关键的能力变化有：

1. **模型配置归一化**：`model-catalog.ts` 成为单一事实来源
2. **视觉模型切换到 `glm-5v-turbo`**：并使用原生 chat completions 路径
3. **`lark-cli` 工具层落地**：艾克斯现在不仅能通过飞书收消息，也能主动调用飞书能力
4. **全流程测试入口**：`/test/message` 可以注入完整处理链路
5. **能力文档与实际代码重新对齐**
